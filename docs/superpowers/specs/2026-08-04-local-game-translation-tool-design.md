# 本地游戏汉化辅助工具设计

## 目标

使用 Python 标准库开发一个轻量级、完全离线的游戏明文资源汉化辅助工具。工具支持命令行和极简 tkinter 图形界面，读取 TXT/常见脚本文本、CSV、JSON 资源，通过本地 JSON 翻译字典将英文、日文或其他原文替换为中文，并导出可继续补充的未翻译清单。

工具只处理用户合法拥有或已获授权的明文资源，不处理加密、压缩、可执行文件或任何保护绕过场景。

## 范围

### 包含

- 单个 `.txt`、`.ks`、`.rpy`、`.script`、`.csv`、`.json` 明文资源文件；其中 `.ks`、`.rpy`、`.script` 按普通文本处理。
- UTF-8 BOM、UTF-8、CP932/Shift-JIS 输入读取。
- UTF-8 无 BOM 汉化输出。
- JSON 格式的“原文到中文”本地翻译字典。
- 结构化替换、结果统计、预览日志和未翻译清单。
- CLI 和仅使用 tkinter 的极简 GUI。
- 标准库 `unittest` 自动化测试。

### 不包含

- 网络翻译 API 或任何联网功能。
- EXE、SO、二进制、压缩包、加密资源和专有封包。
- OCR、图片文字、音频或视频字幕提取。
- 目录递归、批量选择多个文件或格式插件系统。
- YAML、XML 等未明确要求的格式。

## 项目结构

- `translator.py`：编码识别、字典验证、格式解析、文本替换、位置预览、占位符检查、统计与未翻译清单。
- `cli.py`：命令行参数、控制台日志与退出码。
- `gui.py`：tkinter 文件选择、执行按钮、提示框与只读滚动日志。
- `tests/`：核心行为和 CLI 流程的 `unittest` 测试。
- `examples/dictionary.json`：UTF-8 字典模板。
- `README.md`：准备字典、运行 CLI/GUI、格式限制和伦理提示。

CLI、GUI 都调用 `translator.py`，不复制业务逻辑。

## 文件与编码

读取资源时依次尝试：

1. UTF-8 BOM；
2. UTF-8；
3. CP932（Windows 常见 Shift-JIS 超集）；
4. Shift-JIS。

翻译字典必须是 UTF-8 JSON 对象，键和值都必须是字符串。因为 Shift-JIS 无法表示中文，汉化资源统一输出为 UTF-8 无 BOM。日志显示检测到的输入编码和固定的输出编码。

默认汉化文件位于源文件同目录，命名为 `原文件名.zh.扩展名`；默认未翻译清单命名为 `原文件名.untranslated.json`。CLI 可通过 `--output` 和 `--untranslated` 分别指定路径。源文件永不覆盖。重新执行时允许覆盖工具生成的输出目标，并在日志中提示。

两个输出都先写入目标目录中的临时文件，成功刷新并关闭后再通过原子替换更新正式目标。任一步骤失败时清理临时文件，并尽量保留已有输出不变。

## 格式处理和替换规则

### JSON

递归遍历数组和对象，只处理字符串值，不修改对象键名。整个字符串与字典键完全相同时才替换。每个字符串的位置使用类似 `$.menu.items[0].label` 的 JSON 路径表示。使用两空格缩进、`ensure_ascii=False` 写出，因此排版可能改变，但数据结构和非字符串值保持不变。

### CSV

通过标准库 `csv` 读取和写出，逐单元格进行完整字符串精确匹配。使用 `csv.Sniffer` 尝试识别分隔符和引用规则，识别失败时回退到标准 Excel/逗号方言。每个单元格使用一开始计数的“第 N 行第 M 列”表示。格式细节可能由标准库规范化，但行列结构保持不变。

### TXT 和脚本文本

将文件作为普通文本处理。字典键可在行内替换；键重叠时按原文长度从长到短处理，避免短键抢先替换。位置使用一开始计数的行号表示。未翻译候选按处理后的非空行收集。

## 未翻译候选

未翻译清单采用与翻译字典兼容的 JSON 对象格式：

```json
{
  "Options": "",
  "Load Game": ""
}
```

重复原文只保留一项。候选包括包含英文字母、日文字符或中文字符的非空文本；过滤纯数字、网址和明显文件路径。通用文本格式无法完全区分自然语言与程序标识符，因此清单允许出现少量 ID，但未匹配候选不会被写回资源。

JSON 和 CSV 以未匹配的完整字符串值或单元格为候选。TXT/脚本先在原始行中标记已由字典覆盖的片段；如果剩余原文仍包含待翻译内容，则把该行的完整原始文本写入清单。这样人工补全后，完整原始行可在下一次处理时凭最长键优先直接命中。已经被字典完整覆盖的行不进入清单。

## 匹配预览

处理结果记录每个匹配和未匹配候选的原文、译文（若有）及位置。CLI 和 GUI 分别显示前 50 个匹配项与前 50 个未匹配项；超过限制时显示省略数量。示例：

```text
[匹配] JSON $.menu.start: "New Game" -> "新游戏"
[未匹配] CSV 第 3 行第 2 列: "Options"
```

同一原文出现在多个位置时，统计中的未翻译条目仍按原文去重，但预览按实际出现位置记录。

## 占位符安全检查

每次准备应用翻译时，提取并比较原文与译文中的常见运行时标记：

- Python/printf 风格：`%s`、`%d`、`%1` 等；
- 花括号：`{name}`、`{0}`；
- 模板变量：`${name}`；
- 转义换行：`\\n`、`\\r\\n`。

如果译文缺少原文中的标记，记录带位置的警告，但仍然执行替换。译文新增标记或调整标记顺序不视为错误。该检查只做字面标记比较，不尝试解析特定游戏引擎的脚本语法。

## 统计语义

处理结果包含：

- `匹配条目`：本次至少命中过一次的不同字典键数量。
- `实际替换`：所有位置发生替换的总次数。
- `未翻译条目`：去重后的候选数量。
- `占位符警告`：译文缺少原文标记的实际出现位置数量。
- 输入编码、输出编码、汉化文件路径和待翻译清单路径。

CLI 将统计写到标准输出；GUI 在滚动日志框中显示相同信息。

## CLI

基本调用：

```powershell
python cli.py game.json dictionary.json
python cli.py game.csv dictionary.json --output translated.csv
python cli.py game.txt dictionary.json --untranslated todo.json
```

参数错误或处理失败时输出明确错误并返回非零退出码。`--help` 包含合法授权用途提示。成功时先显示带位置的匹配、未匹配和占位符警告预览，再显示汇总统计；每类匹配或未匹配预览最多 50 项。

## GUI

GUI 仅包含：

- 选择资源文件按钮；
- 加载翻译字典按钮；
- 执行汉化按钮；
- 只读滚动日志框；
- 简短合法使用提示。

未选择必要文件、处理成功或处理失败时使用 tkinter 提示框，并将完整信息同步写入日志。GUI 使用与 CLI 相同的默认输出规则。

## 错误处理

以下情况在写出资源前失败，并给出用户可读错误：

- 文件不存在，或扩展名不属于 `.txt`、`.ks`、`.rpy`、`.script`、`.csv`、`.json`；
- 输入编码无法识别；
- 翻译字典不是 JSON 对象，或键/值不是字符串；
- JSON 资源格式无效；
- CSV 无法解析或写出；
- 输出路径与源文件相同；
- 输出文件无法写入。

输出资源先在内存中完成转换，验证成功后再原子写入目标文件，避免解析或写入失败产生半成品。占位符不一致属于警告，不属于处理错误。

## 测试策略

使用标准库 `unittest`，按测试先行实现。覆盖：

- UTF-8、UTF-8 BOM、CP932/Shift-JIS 读取；
- 字典格式验证；
- JSON 只替换字符串值、不修改键名；
- CSV 单元格替换；
- TXT 行内替换及重叠键优先级；
- 匹配条目数、实际替换次数和未翻译条目去重；
- JSON 路径、CSV 坐标和 TXT 行号预览；
- 未翻译候选的基本过滤；
- 常见占位符缺失警告，以及顺序变化不误报；
- CSV 方言识别失败后的逗号方言回退；
- 原子输出成功，以及模拟写入失败时不破坏已有目标；
- 默认与自定义输出路径；
- 不允许覆盖源文件；
- CLI 成功和失败退出码；
- GUI 模块可导入和启动入口存在。

完成标准为：全部测试通过，示例文件可通过 CLI 端到端处理，GUI 可启动且使用同一核心处理函数，README 中的命令与实际 `--help` 一致。

## GitHub 调研后的取舍

- 借鉴 [RPGMTL](https://github.com/MizaGBF/RPGMTL) 的出现位置、出现次数和应用前核对思路，但不引入其项目数据库、插件系统、网页服务或在线翻译组件。
- 借鉴 [Evochron Legacy SE Translation Helper](https://github.com/OniricKaly/Evochron-Legacy-SE-Translation-Helper) 的原文/译文分离和安全输出思路；由于本工具永不原地修改源文件，采用原子生成新文件代替 `.bak` 备份。
- 借鉴 [csv-localizer](https://github.com/rogermolas/csv-localizer) 的清晰 CLI 日志与 CSV 方言适配思路，使用标准库自动识别而不增加依赖。
- 借鉴 [ElexTranslator](https://github.com/TheCodingColibri/ElexTranslator) 的稳定位置和进度上下文，但使用 JSON 路径、CSV 坐标和 TXT/脚本行号代替游戏专用 ID。
- 增加游戏常见占位符缺失警告，只做安全提示，不发展为特定引擎语法分析器。
