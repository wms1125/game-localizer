# 多引擎游戏项目汉化架构设计

> 当前范围说明：本文的多引擎架构原则仍有效，但其中的阶段顺序、Tkinter 交付和部分成熟度判断属于历史设计。当前桌面端为 Electron + React；当前实现状态与引擎能力矩阵以 `README.md` 和 `docs/project-status.md` 为准。HanEngine 不以 Ren'Py 为唯一或默认目标。

## 文档状态

- 日期：2026-08-04
- 状态：已确认设计（自动验证方案修订）
- 目标用户：拥有游戏项目源码、作者提供的明文资源或明确修改授权的开发者与译者
- 设计原则：离线、轻量、标准库优先、按引擎规则处理、默认不修改原项目

本规格扩展现有的单文件汉化工具。原有 JSON、CSV、TXT 和脚本文本处理能力继续保留，但项目模式不再把不同引擎的资源统一当作普通文本，而是通过独立引擎适配器执行检测、提取、写回和验证。

## 目标

新版工具需要完成以下工作：

1. 用户选择游戏项目目录后，自动检测可能使用的游戏引擎并展示置信度和检测证据。
2. 根据检测结果选择独立的引擎适配器，只提取玩家可见文本。
3. 将不同引擎的文本转换为统一、带上下文的本地翻译目录。
4. 使用本地译文目录生成引擎认可或可导入的汉化资源。
5. 在写出前检查占位符、文本标签、字体、源文件变化和输出结构。
6. 默认生成独立输出，并提供清晰的能力等级、风险提示、修改清单和回滚信息。
7. 使用官方样例、开放源码项目和获得明确授权的完整游戏建立多引擎测试矩阵。

## 非目标与伦理边界

本工具不提供以下能力：

- 网络翻译 API、资源上传或自动下载译文；
- 解密、破解、绕过 DRM、反编译可执行文件或规避游戏保护；
- 修改未知二进制资源、Unity 二进制 Asset、Unreal `.locres`/`.pak`/`.ucas`、Godot `.pck` 或 Ren'Py `.rpa`；
- 自动启动从游戏目录发现的可执行文件、脚本或插件；
- 在没有合法权利或明确授权时修改、重新发布游戏资源；
- 承诺所有使用同一引擎的游戏都具有相同资源结构。

检测到封包、二进制或受保护资源时，工具只报告引擎、证据、限制和建议的官方工作流，不尝试提取或修改内容。

## 方案选择

采用“独立引擎适配器”架构，不使用不断扩张的单文件条件分支，也不把外部引擎编辑器设为核心依赖。

选择原因：

- 不同引擎的可翻译单位、上下文、占位符和输出格式不同；
- 每个适配器可以独立开发、测试、标记成熟度和停止支持；
- 核心流程仍可保持标准库实现；
- 安装了官方 SDK 或编辑器时可以增强验证，未安装时不影响基本检测和目录处理；
- 新增引擎不会要求修改已有适配器的内部逻辑。

## 总体架构

```text
游戏项目目录
    ↓
只读项目扫描
    ↓
引擎检测器 → 检测结果、置信度、证据、能力等级
    ↓
高置信度适配器自动选择；不确定时停止并生成异常报告
    ↓
资源清点 → 可翻译 / 不可翻译 / 受保护 / 忽略
    ↓
引擎适配器提取
    ↓
统一翻译目录
    ↓
本地译文目录
    ↓
目录校验 → 占位符 / 标签 / 字体 / 过期原文
    ↓
差异预览 → 独立输出 → 引擎级或结构级验证
    ↓
可选：备份后应用到项目
```

核心模块建议如下：

```text
game_localizer/
├── detector.py
├── catalog.py
├── pipeline.py
├── safety.py
├── models.py
└── adapters/
    ├── base.py
    ├── generic.py
    ├── renpy.py
    ├── rpgmaker.py
    ├── godot.py
    ├── unity.py
    └── unreal.py
```

现有 `translator.py` 的编码读取、字典验证、原子写入和通用格式处理能力逐步迁移到核心模块。迁移期间旧CLI和GUI继续调用兼容入口，不在第一步同时重写所有功能。

## 核心数据模型

### ProjectInfo

描述用户选择的项目根目录、检测到的引擎、源语言、目标语言、检测证据和扫描快照。

### DetectionResult

每个适配器都可以返回候选结果：

- `engine_id`：稳定的引擎标识；
- `display_name`：用户可读名称；
- `score`：0 到 100 的置信度；
- `evidence`：命中的文件、目录或结构特征；
- `capability`：当前适配器对该目录的处理等级；
- `warnings`：资源封包、版本未知或特征冲突等提示。

### ResourceItem

记录项目中的目标资源、相对路径、格式、处理状态、文件哈希和忽略原因。任何写回目标都必须先存在于资源清点结果中。

### TranslationUnit

表示一个可翻译单位，包含稳定 ID、原文、译文、相对文件、结构位置、文本类型、说话者或上下文、占位符、源文本哈希和适配器附加元数据。

### ChangeSet

表示一次准备写出的变更，包含目标相对路径、原文件哈希、新内容、修改条目 ID 和验证结果。核心写入层只接受 ChangeSet，不直接理解引擎语法。

### ValidationIssue

统一表示错误和警告，至少包含严重级别、错误代码、文件、位置、用户可读信息和相关翻译条目。阻断级错误不允许生成或应用输出。

## 自动检测设计

### 检测规则

检测只读取目录结构、文件名、少量明文配置和必要的文件头，不解析大型二进制资源。默认不跟随目录符号链接或 Windows 目录联接点，不扫描项目根目录以外的位置。

置信度规则：

- 80–100：高置信度；只有一个高置信度候选时可自动选择；
- 50–79：中等置信度；自动停止项目处理并写入集中异常报告，用户可在下次运行时显式指定引擎；
- 0–49：不足以确定引擎，不自动选择；
- 两个候选同时达到高置信度，或最高两项分差不超过 10 分时，自动停止并报告冲突，不在当前运行中交互式追问；
- 单个普通扩展名不能单独产生高置信度结果。

检测界面和日志必须显示证据，而不只显示引擎名称。例如：

```text
检测结果：RPG Maker MZ
置信度：98%
证据：
- game.rmmzproject
- js/rmmz_core.js
- data/System.json
能力：完整支持明文项目
```

### 首批检测特征

| 引擎 | 项目级强特征 | 成品或封包特征 | 成品处理等级 |
|---|---|---|---|
| Ren'Py | `game/`、多个 `.rpy`、Ren'Py配置文件 | `renpy/`、`.rpyc`、`.rpa` | 有 `.rpy` 时处理；仅归档时只检测 |
| RPG Maker MZ | `game.rmmzproject`、`js/rmmz_core.js`、`data/System.json` | 部署目录中的同组结构 | 明文JSON存在时可处理 |
| RPG Maker MV | `game.rpgproject`、`js/rpg_core.js`、`data/System.json` | `www/` 下的同组结构 | 明文JSON存在时可处理 |
| Godot | `project.godot`、`.godot/`、项目资源 | 独立 `.pck` 或嵌入PCK | 项目明文可处理；PCK只检测 |
| Unity | `Assets/`、`ProjectSettings/`、`Packages/manifest.json` | `UnityPlayer.dll`、`*_Data/` | 项目官方导出格式可处理；成品只检测 |
| Unreal | `.uproject`、`Config/`、`Content/` | `.pak`、`.ucas`、`.utoc` | PO可处理；封包只检测 |

扫描器跳过 `.git`、缓存、构建结果和各引擎的大型生成目录。具体忽略规则由适配器提供，核心扫描器同时保留一组安全默认值。

## 适配器接口

每个适配器只承担以下职责：

1. `detect`：返回检测分数、证据和能力等级；
2. `inventory`：清点可翻译、忽略、受保护和不支持的资源；
3. `extract`：把引擎资源转换成 TranslationUnit；
4. `validate_catalog`：检查译文的引擎专用占位符、标签和约束；
5. `build_changes`：从已验证目录生成 ChangeSet；
6. `validate_output`：重新解析输出，或调用用户已安装的官方验证工具；
7. `rollback_metadata`：提供应用到原项目时需要的恢复信息。

适配器不直接写文件。所有落盘操作统一交给安全写入层，从而保证路径检查、事务、备份和日志行为一致。

## 能力等级

| 等级 | 含义 |
|---|---|
| 完整支持 | 能提取、写回、验证并生成可直接合并的资源 |
| 辅助支持 | 能生成官方编辑器或本地化管线可导入的文件 |
| 仅检测 | 能识别引擎和限制，但不能处理当前资源形态 |
| 不支持 | 加密、损坏、未知二进制或需要反编译，不继续处理 |

能力等级针对“当前项目目录”而不是只针对引擎。例如，同一 Ren'Py 适配器对包含 `.rpy` 的项目可以是完整支持，对只有 `.rpa` 的发行包则是仅检测。

适配器成熟度与能力等级分开显示：

- 实验性：仅通过格式样本；
- Beta：通过官方样例项目；
- 稳定：通过完整授权游戏、异常场景和运行或官方工具验证。

## 统一翻译目录

新版使用带上下文和稳定 ID 的 JSON 目录。示例：

```json
{
  "schema_version": 1,
  "engine": "renpy",
  "source_language": "en",
  "target_language": "zh_cn",
  "project_fingerprint": "sha256:<computed-at-extraction>",
  "entries": [
    {
      "id": "renpy:script:start:001",
      "source": "Hello, [player_name]!",
      "translation": "你好，[player_name]！",
      "file": "game/script.rpy",
      "location": "label start",
      "type": "dialogue",
      "speaker": "Alice",
      "placeholders": ["[player_name]"],
      "source_hash": "sha256:<computed-from-source>"
    }
  ]
}
```

### ID规则

稳定 ID 按以下优先级生成：

1. 引擎原生翻译身份，例如 Ren'Py翻译标识、Unity表和键、Unreal上下文；
2. 稳定结构位置，例如 RPG Maker数据库路径或地图事件命令位置；
3. 相对文件、文本类型、结构位置和原文哈希组成的确定性ID；
4. 行号只作为显示信息，不作为首选身份来源。

同一原文在不同上下文可以拥有不同译文。重新提取时，ID和源文本哈希都一致才直接复用译文；ID一致但源文本变化时自动标记为过期、排除写回并集中报告，不要求在当前运行中逐条复核。

### 旧字典兼容

现有简单字典继续支持：

```json
{
  "New Game": "新游戏"
}
```

兼容规则：

- 原文在目录中只有一个上下文，或所有上下文允许相同译文时，旧字典可以直接应用；
- 同一原文存在多个需要区分的上下文时，自动停止这些歧义条目的写回并在集中报告中提示改用统一目录；
- 旧的单文件CLI保持原有精确匹配和输出行为；
- 项目模式导出的待翻译清单使用统一目录，不再导出程序代码组成的完整文本行。

## 自动验证与低人工介入

项目模式以“正常情况零逐条确认、异常情况集中处理”为默认行为。工具不要求工作人员逐条阅读匹配结果，也不把人工抽样作为生成汉化文件的完成条件。

### 自动决策结果

每次运行只产生三种决策：

- `PASS`：所有技术检查通过，直接生成独立汉化输出；
- `PASS_WITH_WARNINGS`：存在不影响结构安全的风险，仍生成输出并写入汇总报告；
- `STOPPED`：存在可能破坏项目或无法确定处理目标的问题，不生成有风险的输出，只写入异常报告。

决策针对整个ChangeSet。默认不弹出逐条确认窗口，也不让用户在一次运行中反复回答问题。

### 自动检查项目

工具自动完成：

- 引擎置信度和特征冲突检查；
- 目录条目身份、上下文歧义和源文本过期检查；
- 占位符、插值、复数分支、转义和引擎文本标签检查；
- JSON、CSV、PO以及引擎专用输出的重新解析；
- 修改节点白名单和非目标数据不变性检查；
- 源文件扫描快照和写回前哈希检查；
- 目标路径、符号链接、目录联接、路径碰撞和项目边界检查；
- 字体字符覆盖率检查；
- 译文长度增长、换行增长和潜在界面溢出风险评分；
- 可用时调用官方Lint、导入器或编译验证；
- 独立输出清单、备份清单和事务回滚检查。

### 自动风险分级

以下情况直接产生 `STOPPED`：

- 引擎检测冲突或当前资源只有“仅检测/不支持”能力；
- 译文缺少语法关键占位符、插值、标签或复数分支；
- 源文本已经变化、目录身份冲突或旧字典出现上下文歧义；
- 字体对目标语言字符完全不覆盖；
- 输出无法重新解析、官方验证失败或目标路径不安全；
- 写回无法保证事务和恢复完整性。

以下情况产生 `PASS_WITH_WARNINGS`：

- 字体只缺少少量译文字符；
- 译文长度或换行增长可能造成界面溢出；
- 译文与原文完全相同；
- 没有安装官方验证器，只能完成结构验证；
- 仍有未翻译条目，但已翻译部分可以安全输出。

风险阈值由适配器版本和自动化测试固定，不在每次运行时要求工作人员调整。路径、事务、解析和关键占位符检查不可关闭。

### 集中异常报告

工具同时生成机器可读JSON和简短文本报告。问题按严重级别和错误代码分组，重复问题合并，报告包含数量、文件、结构位置、原因和建议动作。控制台和GUI只显示摘要，例如：

```text
自动验证：STOPPED
阻断问题：2类，共7处
- PLACEHOLDER_MISSING：5处
- ENGINE_DETECTION_CONFLICT：2处
完整报告：validation-report.json
```

工作人员只处理报告中的异常类别，不需要检查所有成功条目。修正译文或显式选择引擎后重新运行，工具只重新报告仍未解决的问题。

### 自动化边界

工具可以自动保证支持范围内的文件结构、引擎语法、占位符、路径和写回事务安全，但不能仅靠程序证明译文语义、语气和文化表达完全正确。语义抽样检查作为可选功能保留，默认关闭，也不影响技术验证通过后的独立输出生成。

## 引擎专用方案

### Ren'Py

- 识别说话者对白、旁白、菜单选项、可翻译字符串和角色显示名；
- 跳过注释、`label`、变量、跳转、媒体命令、资源路径和Python代码；
- 保护方括号插值、花括号文本标签、转义和Ren'Py控制标记；
- 输出到 `game/tl/zh_cn/`，不复制包含原始标签的完整脚本到原目录；
- 检查项目字体是否覆盖译文字符；
- 检测到用户安装的Ren'Py SDK时，可运行官方Lint；未检测到时执行语法和结构验证；
- 不读取 `.rpyc` 或 `.rpa` 中的文本。

### RPG Maker MV/MZ

- 区分MV与MZ，不假设两个版本的数据结构完全相同；
- 按数据库字段和事件命令白名单提取名称、描述、消息、选项和系统术语；
- 跳过图片、音频、地图资源名、脚本、插件命令和内部标识；
- 保留控制字符、颜色代码、变量引用、角色名引用和插件规定的文本标记；
- 输出修改后的 `data/*.json`，保持相对路径；
- 默认不改插件脚本中的字符串，只有以后为特定插件增加独立规则时才处理；
- 写回后重新解析所有修改JSON并核对非目标结构。

### Godot

- 优先支持项目使用的翻译CSV和Gettext PO；
- 识别项目配置中登记的翻译资源；
- 对脚本和场景只提取明确标记为可翻译的字符串，不扫描任意代码字符串；
- 输出 `.po` 或翻译CSV，不直接修改二进制 `.translation`；
- `.pck`、嵌入式PCK和压缩二进制资源只检测；
- 检测到Godot编辑器时可进行无窗口导入或项目验证，否则执行PO、CSV和项目引用检查。

### Unity

- 检测项目版本和 Localization Package 配置；
- 第一阶段处理 Localization Package 官方导出的CSV或XLIFF；
- 保留表名、Entry ID、Locale、Smart String变量、复数和元数据；
- 不直接修改序列化Asset或发行包中的二进制资源；
- 项目未配置官方本地化包时，给出资源清点和导出指引，不扫描所有C#字符串；
- 检测到Unity编辑器时可以生成待执行的导入和验证命令，但不自动安装或启动编辑器。

### Unreal

- 第一阶段处理本地化管线导出的PO；
- 保留 `msgctxt`、命名空间、键、复数、注释和文件头；
- 不直接修改 `.locres`、`.locmeta`、`.uasset`、`.pak`、`.ucas` 或 `.utoc`；
- 项目只包含manifest/archive时可以清点，但推荐通过官方流程导出PO；
- 检测到Unreal工具链时可以提供导入、编译和验证命令，不自动运行未知项目代码。

### 通用回退

- 保留现有JSON、CSV、TXT和脚本文本单文件能力；
- 用户必须明确选择通用模式，自动检测不确定时不把项目当作通用文本批量修改；
- 通用模式不承诺理解引擎语法；
- 项目级通用处理只使用用户选择的文件或明确包含规则。

## 安全写回流程

### 默认独立输出

项目模式默认写入用户指定的 `localized-output/`：

- 只生成发生变化的文件；
- 保留相对目录结构；
- 不复制大型媒体资源；
- 生成 `manifest.json`，记录项目指纹、适配器版本、源文件哈希、目标文件哈希、修改条目和验证结果；
- 输出目录不会在后续扫描中被再次当作源资源；
- 源项目在默认流程中保持不变。

### 可选应用到项目

只有用户明确选择“应用到项目”时才允许覆盖：

1. 校验所有目标都位于所选项目根目录；
2. 拒绝通过符号链接、目录联接或路径穿越写到项目外；
3. 对照扫描快照检查源文件哈希，发现变化立即停止；
4. 在项目内的专用备份目录保存原文件和恢复清单；
5. 完整暂存全部新文件；
6. 以事务方式替换目标；
7. 任一步失败时恢复本次已经替换的文件；
8. 验证完成后保留备份，直到用户自行确认删除。

工具不提供自动删除备份的默认操作。

### 自动写回门禁

只有 `PASS` 和 `PASS_WITH_WARNINGS` 的ChangeSet可以进入安全写入层。`STOPPED` 不创建、不暂存也不覆盖任何汉化目标，只生成集中异常报告。

`PASS_WITH_WARNINGS` 在默认独立输出模式下不要求人工确认。应用到原项目仍需要一次整体授权确认；该确认只决定是否覆盖项目，不要求逐条检查翻译内容。

## CLI设计

项目模式新增子命令：

```text
game-localizer detect <项目目录>
game-localizer extract <项目目录> --output catalog.json
game-localizer apply <项目目录> catalog.json --output localized-output
game-localizer validate <项目目录或输出目录>
game-localizer engines
```

共同参数包括显式引擎选择、源语言、目标语言、日志详细度和机器可读报告路径。`detect` 和 `extract` 永远不修改项目；`apply` 默认生成独立输出。应用到项目需要单独、明确的参数，不能由路径巧合触发。

项目模式支持无人值守运行，并使用稳定退出码：

- `0`：`PASS` 或 `PASS_WITH_WARNINGS`，独立输出已经生成；
- `1`：输入、读写或内部处理失败；
- `2`：自动验证得到 `STOPPED`，项目未修改且异常报告已经生成。

现有调用继续保留：

```text
python cli.py <单个资源文件> <简单字典>
```

兼容命令不自动进行项目扫描或引擎推断。

## GUI设计

GUI继续只使用tkinter，维持极简工具定位。项目模式包含：

- 选择游戏项目目录；
- 自动检测引擎；
- 导出或加载翻译目录；
- 生成汉化文件；
- 简单日志和风险提示。

检测结果区域只展示引擎、置信度、能力等级和关键证据。复杂条目编辑、在线翻译、账号、云同步、图片OCR和大型项目管理不进入GUI范围。

默认流程自动完成检测、验证和独立输出，不显示逐条确认。得到 `STOPPED` 时，GUI只显示问题类别、数量和报告路径。“应用到项目”属于高级操作，只保留一次整体覆盖确认和清晰的备份说明。

## 外部工具与依赖

- 核心检测、目录、PO/CSV/JSON处理、安全写入和CLI使用Python标准库；
- 不在运行时自动安装Python包；
- 不自动下载引擎SDK、编辑器或样例项目；
- 用户已经安装官方引擎工具时，适配器可以发现其路径并提供增强验证；
- 外部验证命令必须记录在报告中；
- 不执行从待汉化项目中发现的可执行文件、插件或任意脚本。

## 测试策略

### 四层测试

| 层级 | 目的 | 内容 |
|---|---|---|
| 检测测试 | 防止认错引擎 | 完整特征、缺失特征、混合目录、嵌套项目和伪装扩展名 |
| 适配器测试 | 保证只处理目标文本 | 对白、菜单、代码、注释、资源路径、占位符和上下文冲突 |
| 官方项目测试 | 验证真实结构 | 官方样例、开放源码项目和多个引擎版本 |
| 运行验证 | 确认输出可用 | 官方Lint、导入、编译、启动烟雾测试和回滚 |

### 首批测试来源

| 引擎 | 测试来源 | 主要验证点 |
|---|---|---|
| Ren'Py | 已测试的开放源码游戏Open，以及包含插值和文本标签的第二个授权项目 | `tl/zh_cn`、菜单、字体、Lint和存档相关ID |
| RPG Maker MZ | 官方示例项目和官方样例游戏 | 数据库、地图事件、选项、控制字符和插件边界 |
| RPG Maker MV | 获得明确许可的开放源码MV项目 | MV/MZ差异和部署目录结构 |
| Godot | MIT许可的官方Godot Demo Projects | `project.godot`、PO、CSV和明确翻译标记 |
| Unity | Unity Localization Package官方样例 | String Table、Smart String、CSV/XLIFF往返 |
| Unreal | Epic官方样例项目或最小授权项目 | PO上下文、命名空间、导入和编译 |
| 通用模式 | 仓库内小型JSON、CSV、TXT样本 | 编码、格式、安全输出和旧接口兼容 |

大型官方项目不提交到本仓库。测试报告记录来源、许可证或授权依据、版本、下载日期、文件哈希、使用的引擎工具版本和测试结果。仓库只保存许可允许的小型夹具和由项目团队创建的最小格式样本。

### 验收标准

自动检测：

- 所有纳入矩阵的官方样例都识别正确；
- 跨引擎样例之间不存在高置信度误判；
- 每次结果都有可复核证据；
- 删除一个弱特征不会让具有多个强特征的项目完全失去识别结果；
- 封包成品不会错误标记为完整支持。

提取：

- 金标准夹具中的玩家可见文本提取率为100%；
- 金标准夹具中的代码、注释、内部ID和资源路径误提取数为0；
- 相同原文的不同上下文拥有不同稳定ID；
- 未修改项目重复提取时ID保持一致；
- 无译文往返不会改变项目文件。

写回：

- 只有目录中已翻译的目标节点发生变化；
- 修改后的结构化文件都能重新解析；
- 默认流程中源项目所有文件哈希不变；
- 回滚后目标文件哈希与备份前一致；
- 模拟任一文件暂存或提交失败时不留下部分应用状态。

验证：

- 所有引擎关键占位符和标签缺失都被阻止；
- 中文字体缺失能够被发现并给出文件级证据；
- 有官方验证器时，稳定适配器必须通过官方验证；
- 没有验证器时，报告明确标记验证边界；
- 实验性、Beta和稳定状态与实际测试证据一致。

自动化流程：

- 低风险官方样例从检测到独立输出全程不出现逐条人工确认；
- 相同项目、目录和适配器版本重复运行时得到相同自动决策和问题分类；
- `STOPPED` 不产生待合并资源，也不修改源项目；
- 集中报告按错误代码合并重复问题，并提供全部原始位置；
- CLI退出码与 `PASS`、`PASS_WITH_WARNINGS`、`STOPPED` 和处理失败准确对应；
- GUI对一次运行最多显示一个结果摘要，不为每个条目弹出对话框。

现有单文件回归：

- 现有全部自动化测试继续通过；
- 旧CLI参数、默认输出名和简单字典保持兼容；
- 当前JSON和CSV安全写入语义不因项目模式而退化。

## 分阶段实施

### 阶段一：适配器基础与自动检测

- 建立数据模型、适配器基类、注册表和项目扫描器；

### 阶段二：Ren'Py与RPG Maker完整支持

- 实现Ren'Py语法提取、目录、字体检查和 `tl/zh_cn` 输出；

- 实现统一目录、结构写回、独立输出、备份和回滚；
- 在授权完整游戏上执行提取、写回和验证。

完成条件：两个适配器至少达到Beta；只有通过完整游戏验证的适配器才能标记稳定。

### 阶段三：Godot完整支持

- 实现PO、翻译CSV和项目翻译资源识别；
- 实现明确翻译标记的提取；
- 实现Godot项目或结构验证；
- 保持PCK为仅检测。

完成条件：官方Demo和授权项目的往返测试通过。

### 阶段四：Unity和Unreal辅助支持

- 实现Unity Localization CSV/XLIFF目录转换；
- 实现Unreal PO读取、上下文保留和写出；
- 提供官方导入/编译命令和验证报告；
- 保持二进制Asset、LocRes和封包为仅检测。

完成条件：官方样例的导出、翻译、重新导入流程通过。

### 阶段五：极简GUI和发布文档

- 增加项目目录选择、检测、目录导入导出和生成操作；
- 显示能力等级、成熟度、证据、风险和验证边界；
- 编写每种引擎的准备要求、支持范围和伦理说明；
- 发布前执行完整测试矩阵和干净环境安装测试。

## 最终成功标准

新版被视为达到设计目标，需要同时满足：

1. 用户选择项目目录后能得到可解释的引擎检测结果；
2. 不支持的封包或二进制资源不会被误修改；
3. Ren'Py和RPG Maker能够生成经过真实项目验证的引擎专用输出；
4. Godot能够通过官方翻译资源完成往返；
5. Unity和Unreal能够生成官方流程可导入的本地化文件；
6. 统一目录能够保存上下文、稳定身份、占位符和过期状态；
7. 默认处理不改变源项目，应用模式具备事务、备份和恢复证据；
8. 正常项目能够从检测到独立输出全自动完成，不要求逐条人工校验；
9. 无法安全确定的情况自动停止并集中报告，不带风险继续写入；
10. 每个引擎的能力等级和成熟度都由自动化测试和真实项目结果支撑；
11. 工具继续保持本地优先、标准库优先的 Python 核心与 Electron + React 桌面端；
12. 所有处理都遵守合法授权、不得破解和不得绕过保护的边界。
