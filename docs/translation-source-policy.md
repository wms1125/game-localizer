# Translation Source Policy

更新时间：2026-08-08

本策略把“来源可追溯”和“译文质量可信”分开处理。来源登记可以证明一份文本来自哪里、由哪个版本产生；它不会自动证明中文译文准确、自然或适合另一个项目。

## 权威等级

1. **项目批准术语表**：由项目权利人或指定审校人批准，带版本、审校记录和适用范围。它是项目内术语决策的最高优先级。
2. **权利清晰且人工审校的项目译文**：必须有可核验的仓库/版本、许可或授权引用、文件哈希和审校范围。
3. **官方引擎与平台资料**：用于确认语法、控件名称和运行时语义；只有在明确提供目标语言术语时，才可作为术语候选。
4. **通用语言规范和术语资料**：例如 Unicode/CLDR 等公开规范，用于格式、语言标识和本地化约定，不替代项目语境审校。
5. **机器翻译、未署名词典和社区译文**：只能作为候选建议，不能单独进入发布字典或声称“权威”。

## 当前登记源

`docs/translation-sources.json` 登记了 Ren'Py 官方发行包中的 `The Question` 样例（发行包 `8.5.3.26051504`，上游参考提交 `3baa108`）及其 `schinese` 文件哈希。发行包版本和上游提交是两个独立的证据点。该来源的权威范围是：

- 对 Ren'Py 示例工程结构、`translate` 语法、界面路径和运行时行为的参考；
- 在本机隔离环境中构建中文候选并执行截图回归；
- 为通用 Ren'Py UI 词语提供人工审校起点。

它**不是**中文翻译质量认证，也不是任何具体游戏的术语表。SDK `LICENSE.txt` 说明 Ren'Py 大部分代码采用 MIT，同时包含 LGPL 和多个第三方组件条款；因此本仓库只登记来源和哈希，不复制这些样例译文或资源。任何需要随产品分发的译文仍须单独完成许可证、署名和项目权利审查。

## 进入发布术语表的最低条件

- 每个条目都有来源 ID、原文、目标语、语境键和审校状态；
- 来源能回溯到固定版本或固定文件哈希；
- 至少一名人工审校人确认语义、语体、专名和 UI 长度；
- 占位符、富文本标签和换行约束通过自动校验；
- 对来源译文的许可或授权结论已记录；不确定时保持为本地候选，不进入发布物。

`.tmp/heartfelt-dictionary.json` 是机械占位符字典，`Heartfelt Moments` 的上游项目也是独立的第三方项目；它们不能作为本策略的中文质量权威。
